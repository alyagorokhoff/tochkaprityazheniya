## Установка, сборка и запуск

Стандартная установка по lock-файлу:

```bash
npm ci
```

Эквивалентная проверенная установка через служебный скрипт проекта:

```bash
npm run install:ci
```

Разработка:

```bash
npm run dev
```

Production-сборка:

```bash
npm run build
```

Локальный запуск собранного приложения:

```bash
npm run start
```

Проверки:

```bash
npm run lint
npm test
```

Существующая конфигурация ориентирована на Cloudflare Workers через Vinext. Для получения того же поведения без изменения исходников внешнее размещение должно поддерживать Cloudflare Workers/Vinext. Перенос на обычный Node.js-сервер или другой serverless runtime может потребовать смены runtime-адаптера и уже будет отдельной доработкой, которой в этом пакете намеренно нет.

## Структура проекта

- `app/` — layout, главная страница, глобальные стили и необязательные SIWC/ChatGPT auth helpers.

- `scripts/` — воспроизводимые скрипты установки и сборки.

## Переменные окружения

Обязательных секретных env-переменных у текущей рабочей версии нет. Полный безопасный пример находится в `.env.example`.

Необязательные служебные переменные:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `SITES_INSTALL_TIMEOUT` | Максимальное время `npm ci` в служебном скрипте | `8m` |
| `SITES_INSTALL_KILL_AFTER` | Пауза перед принудительной остановкой установки | `15s` |
| `SITES_BUILD_TIMEOUT` | Максимальное время Vinext build | `3m` |
| `SITES_BUILD_KILL_AFTER` | Пауза перед принудительной остановкой сборки | `10s` |

| `SITES_NPM_CACHE_SEED` | Необязательный предварительно наполненный npm-кеш | пусто |
| `WRANGLER_WRITE_LOGS` | Запись логов Wrangler | `false` |
| `WRANGLER_LOG_PATH` | Путь логов Wrangler | `.wrangler/logs` |
| `MINIFLARE_REGISTRY_PATH` | Путь реестра Miniflare | `.wrangler/registry` |

`SITES_ENV_READY` и `SITES_PROJECT_ROOT` выставляются самими скриптами и не должны задаваться вручную. `CODEX_SANDBOX` влияет только на режим file watching во внутреннем preview и не нужен на внешнем хостинге.

Файл `.env.example` попадает под исходное правило `.env*` в `.gitignore`. При первом добавлении распакованного проекта в новый Git-репозиторий добавьте его явно командой `git add -f .env.example` либо отдельно скорректируйте `.gitignore` уже после переноса.

## Контрольный список переноса

1. Распаковать архив и создать новый Git-репозиторий.
2. Добавить все файлы, включая принудительное добавление `.env.example` из-за исходного правила `.env*`.
3. Установить Node.js `>=22.13.0` и npm.
4. Выполнить `npm ci`.
5. Выполнить `npm run build`.
6. Настроить Cloudflare Workers/Vinext и bindings `ASSETS`/`IMAGES` в целевом аккаунте либо заранее согласовать отдельную адаптацию под другой runtime.
7. Выполнить `npm run start` для локальной проверки.
8. Проверить CTA-переходы в Telegram и WhatsApp.

Для текущей версии не требуется импорт БД, миграция таблиц, перенос файлового хранилища, секретов, webhook или пользовательских записей.
